离线 Docker 镜像构建执行计划

适用于机器 A 无网络但有 Docker、机器 B 为 Windows 且有网络但不能安装 Docker/WSL 的场景。 B 只打包源码、前端 dist 和可选 Go module 离线缓存；A 使用本地 Docker 镜像完成 Go 编译与最终镜像构建。

机器 A 有 Docker，无网络；可以是 Linux，也可以是 Windows Server 2019，但 Docker 必须能构建 Linux 容器镜像。
机器 B Windows，有网络，不能安装 Docker/WSL，不能作为代理；只运行 Bun/Node 脚本并传输离线包。
目标 A 在无网络条件下，用本地 builder/runtime 镜像、前端 dist 和 Go 离线依赖构建 new-api 镜像。

总体策略

不按当前项目 Dockerfile 原样离线构建。原 Dockerfile 会执行 bun install、go mod download 和 apt-get， 这些步骤都需要网络，不适合机器 A。

当前方案使用 scripts/package-offline-inputs.cjs 在 B 上生成离线输入包。 包内包含当前源码、web/default/dist、web/classic/dist 占位文件； 首次传输或 go.mod/go.sum 变化时，再额外包含 offline/gomodproxy。

Go 二进制不在 B 上编译。A 使用 Dockerfile.offline，在本地 golang:1.26.1-alpine builder 镜像中编译 Go，再复制到本地 runtime 镜像中。

当前项目的 main.go 同时 embed web/default/dist 和 web/classic/dist。classic 前端不需要完整构建，但必须有 web/classic/dist/index.html 占位文件。

逐步执行计划

1. 在机器 A 准备本地 Docker 镜像

A 无网络，所以 builder、runtime 和生产 Compose 依赖镜像必须提前放到 A 并加载。下面的文件名按实际 tar 文件调整。

A / Bash 
docker load -i golang-1.26.1-alpine-amd64.tar
docker load -i new-api-runtime-base-bookworm-slim-amd64.tar
docker load -i redis-7.2-alpine-amd64.tar
docker load -i postgres-15-alpine-amd64.tar
docker load -i apache-kafka-3.7.1-amd64.tar
docker load -i clickhouse-server-24.8-amd64.tar

docker image inspect golang:1.26.1-alpine
docker image inspect new-api-runtime-base:bookworm-slim-amd64
docker image inspect redis:7.2-alpine
docker image inspect postgres:15-alpine
docker image inspect apache/kafka:3.7.1
docker image inspect clickhouse/clickhouse-server:24.8
A / PowerShell 
docker load -i .\golang-1.26.1-alpine-amd64.tar
docker load -i .\new-api-runtime-base-bookworm-slim-amd64.tar
docker load -i .\redis-7.2-alpine-amd64.tar
docker load -i .\postgres-15-alpine-amd64.tar
docker load -i .\apache-kafka-3.7.1-amd64.tar
docker load -i .\clickhouse-server-24.8-amd64.tar

docker image inspect golang:1.26.1-alpine
docker image inspect new-api-runtime-base:bookworm-slim-amd64
docker image inspect redis:7.2-alpine
docker image inspect postgres:15-alpine
docker image inspect apache/kafka:3.7.1
docker image inspect clickhouse/clickhouse-server:24.8

如果 A 上镜像标签不同，后续 docker build 使用 --build-arg 指定。

2. 在机器 B 准备 portable 工具

B 不需要 Docker 或 WSL，只需要这些命令可用。

  • bun：构建 web/default 并运行脚本。
  • node：可替代 Bun 来运行脚本，但构建前端仍需要 bun。
  • go：仅在使用 --include-go-modules 打包 Go 离线依赖时需要。
  • tar：用于生成 .tar.gz，Windows Server 2019 通常自带。
  • pscp 或 OpenSSH scp：用于向 A 传输离线包。

3. 首次传输或 Go 依赖变化时，在 B 打包完整输入

当 A 还没有 offline/gomodproxy，或 go.mod/go.sum 发生变化时使用这个命令。

B / PowerShell 或 CMD 
bun scripts/package-offline-inputs.cjs --include-go-modules

如果只想用 Node 执行脚本，也可以这样运行；脚本内部仍会调用 bun 构建前端。

B / PowerShell 或 CMD 
node scripts/package-offline-inputs.cjs --include-go-modules

产物路径：

B / 输出文件 
.offline\new-api-offline-inputs-with-gomod.tar.gz

4. 日常代码或前端变化时，在 B 只打包源码和 dist

如果 go.mod 和 go.sum 没变，A 可以复用之前保存的 gomodproxy。

B / PowerShell 或 CMD 
bun scripts/package-offline-inputs.cjs

产物路径：

B / 输出文件 
.offline\new-api-offline-inputs-dist.tar.gz

5. 判断是否需要重新传 Go 依赖

在 B 或任意有 Git 的机器上，对比上次 A 构建使用的提交和当前提交。

Git 
git diff --name-only 上次构建提交..当前提交 -- go.mod go.sum

没有输出时，只传 new-api-offline-inputs-dist.tar.gz；有输出时，传带 --include-go-modules 的完整包。

6. 从机器 B 传输到机器 A

下面以 PuTTY 的 pscp 为例。首次或依赖变化传完整包。

B / PowerShell / pscp 
pscp .\.offline\new-api-offline-inputs-with-gomod.tar.gz user@A:/tmp/

日常更新传 dist 包。

B / PowerShell / pscp 
pscp .\.offline\new-api-offline-inputs-dist.tar.gz user@A:/tmp/

如果 B 有 OpenSSH 客户端，也可以使用 scp。

B / PowerShell / scp 
scp .\.offline\new-api-offline-inputs-dist.tar.gz user@A:/tmp/

7. Linux A：首次或依赖变化时解包并构建

完整包会更新 A 侧持久化的 Go 离线依赖缓存。

A / Bash 
BUILD_DIR="$HOME/new-api-offline-build"
CACHE_DIR="$HOME/new-api-offline-cache"

rm -rf "$BUILD_DIR"
mkdir -p "$BUILD_DIR" "$CACHE_DIR"
tar -xzf /tmp/new-api-offline-inputs-with-gomod.tar.gz -C "$BUILD_DIR"
cd "$BUILD_DIR"

test -f web/default/dist/index.html
test -f web/classic/dist/index.html
test -d offline/gomodproxy

rm -rf "$CACHE_DIR/gomodproxy"
cp -a offline/gomodproxy "$CACHE_DIR/gomodproxy"

docker build --pull=false --network=none -f Dockerfile.offline -t new-api-local:offline .

8. Linux A：日常更新时复用 Go 离线依赖并构建

A / Bash 
BUILD_DIR="$HOME/new-api-offline-build"
CACHE_DIR="$HOME/new-api-offline-cache"

rm -rf "$BUILD_DIR"
mkdir -p "$BUILD_DIR"
tar -xzf /tmp/new-api-offline-inputs-dist.tar.gz -C "$BUILD_DIR"
cd "$BUILD_DIR"

mkdir -p offline
cp -a "$CACHE_DIR/gomodproxy" offline/gomodproxy

test -f web/default/dist/index.html
test -f web/classic/dist/index.html
test -d offline/gomodproxy

docker build --pull=false --network=none -f Dockerfile.offline -t new-api-local:offline .

9. Windows Server 2019 A：首次或依赖变化时解包并构建

A / PowerShell 
$BuildDir = "C:\new-api-offline-build"
$CacheDir = "C:\new-api-offline-cache"

Remove-Item $BuildDir -Recurse -Force -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force $BuildDir | Out-Null

docker build --pull=false --network=none -f Dockerfile.offline -t new-api-local:offline .

11. 镜像标签不同时的构建命令

如果 A 上 builder 或 runtime 镜像不是默认标签，使用 build args。

A / Bash 或 PowerShell 
docker build --pull=false --network=none --build-arg GO_BUILDER_IMAGE=your-go-builder:tag --build-arg RUNTIME_IMAGE=your-runtime:tag -f Dockerfile.offline -t new-api-local:offline .

12. 在机器 A 启动生产离线 Compose 验证

A / Bash 或 PowerShell 
docker compose -f docker-compose.prod-offline.yml up -d

另开终端执行基础访问检查。

A / Bash 
curl -I http://127.0.0.1:3000
A / PowerShell 
Invoke-WebRequest -Method Head http://127.0.0.1:3000

验收标准

  • B 上脚本能生成 .offline/new-api-offline-inputs-with-gomod.tar.gz 或 .offline/new-api-offline-inputs-dist.tar.gz。
  • B 上生成的包包含 web/default/dist/index.html。
  • B 上生成的包包含 web/classic/dist/index.html 占位文件。
  • 首次包或依赖变化包包含 offline/gomodproxy。
  • A 上已加载 golang:1.26.1-alpine、runtime 镜像和生产 Compose 依赖镜像，或构建时显式传入对应 --build-arg。
  • A 上 docker build --pull=false --network=none -f Dockerfile.offline -t new-api-local:offline . 成功完成。
  • A 上构建过程中没有任何需要联网的步骤。
  • Go 编译发生在 A 的 Docker builder 镜像中，B 不需要产出 new-api 二进制。
  • A 上 docker images 能看到 new-api-local:offline。
  • A 上 docker compose -f docker-compose.prod-offline.yml up -d 能启动应用、Postgres、Redis、Kafka 和 ClickHouse。
  • 容器启动时不出现 exec format error、no such file or directory 或权限错误。
  • 访问 http://A机器IP:3000 能打开前端页面。
  • curl -I http://127.0.0.1:3000 或 PowerShell Invoke-WebRequest 能返回 HTTP 响应。

验收命令

B / PowerShell 或 CMD 
tar -tzf .\.offline\new-api-offline-inputs-with-gomod.tar.gz | findstr /C:"web/default/dist/index.html" /C:"web/classic/dist/index.html" /C:"offline/gomodproxy"
A / Bash 
cd "$HOME/new-api-offline-build"
test -f web/default/dist/index.html
test -f web/classic/dist/index.html

docker compose -f docker-compose.prod-offline.yml ps

常见失败判断

现象 高概率原因 处理方式
no matching manifest 或 Windows 镜像相关错误 A 的 Docker 当前不能构建 Linux 容器镜像，或处于 Windows container 模式。 切换到 Linux container 支持的 Docker 环境；本项目最终镜像是 Linux 镜像。
go: module lookup disabled by GOPROXY=off offline/gomodproxy 缺模块，通常是 go.mod/go.sum 变了但只传了 dist 包。 在 B 上重新执行 bun scripts/package-offline-inputs.cjs --include-go-modules 并传完整包。
Go 编译时报 embed 缺文件 web/default/dist 或 web/classic/dist 缺失。 重新运行 B 侧脚本；classic 只需要占位 index.html。
A 上 Docker build 尝试联网 使用了原始 Dockerfile，或未使用 --network=none 检查隐藏联网步骤。 改用 Dockerfile.offline，并保留 --pull=false --network=none。
pull access denied 或找不到 builder/runtime 镜像 A 本地没有加载对应镜像，或镜像标签和 Dockerfile 默认值不一致。 先 docker load，或通过 --build-arg GO_BUILDER_IMAGE=... 和 --build-arg RUNTIME_IMAGE=... 指定本地标签。
HTTPS 请求证书失败 runtime 镜像缺 CA 证书。 使用预装 ca-certificates 的 runtime 镜像，例如 new-api-runtime-base:bookworm-slim-amd64。
